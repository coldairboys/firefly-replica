# 新手先看：项目目录、配置文件和发布流程

> [!TIP]
> **系列导读**：
> 欢迎来到《Firefly 博客搭建指南》系列！如果你刚接触这个博客项目，最容易懵的不是代码，而是“到底该改哪个文件”、“本地预览和线上发布怎么做”。建议先看完本篇全景说明，再按部就班进入后续具体功能篇章。

## 先记住这 4 句话

1. **写文章看这里**：项目真正读取的文章目录是 `src/content/posts/`
2. **改设置看这里**：绝大多数站点外观与功能配置都在 `src/config/` 目录中
3. **本地开发调试**：使用 `pnpm dev` 启动实时热重载预览
4. **一键构建与上线**：本地验证无误后运行 `.\publish-blog.bat` 自动推送

记住这四点，后面的操作就不会混乱。

## 这个项目最常改的目录

### 1. 文章内容目录

```text title="src/content/posts/"
src/content/posts/
├── 0.md          # 当前新手导读
├── 1.md          # 部署指南
└── ...
```

你日常写文章、修改历史博文，核心工作区就在这里。

### 2. 站点配置目录

```text title="src/config/"
src/config/
├── siteConfig.ts        # 站点主配置（标题、域名、页面开关、分析工具等）
├── navBarConfig.ts      # 顶部导航栏配置
├── commentConfig.ts     # 评论系统（Giscus / Waline 等）
├── musicConfig.ts       # 悬浮音乐播放器配置
├── pioConfig.ts         # 看板娘交互模型配置
├── sidebarConfig.ts     # 侧边栏小组件与广告位
└── ...
```

修改网站标题、开关功能、替换主题色彩，都在该目录下对应的配置文件中完成。

### 3. 公共静态资源目录

```text title="public/"
public/
├── favicon/             # 网站图标
├── assets/images/       # 赞助码、站内公开图片
└── assets/audio/        # 本地音乐文件
```

放在 `public/` 下的文件在打包时会原样复制到根路径，可通过 `/favicon/...` 直接在浏览器中访问。

### 4. 特殊单页面目录

```text title="src/content/spec/"
src/content/spec/
├── about.md             # 关于页文案
├── friends.mdx          # 友情链接页及申请说明
└── guestbook.md         # 留言板导语
```

## 为什么有时候修改了文件，页面却没有变化？

新手最常遇到的“改了不生效”通常有以下 3 种原因：

### 1. 修改了非生产目录文件
有的同学误改了 `src/content/17.md`，但 Astro Content Collections 规范真正读取的是：
`src/content/posts/17.md`。请确保路径在 `posts/` 子目录下。

### 2. 本地服务缓存未更新
Astro 具备极速的 Vite 热更新能力，但在修改深层 TypeScript 配置时，建议：
1. 保存文件（`Ctrl + S`）；
2. 刷新浏览器页面；
3. 若仍未变化，在终端中按 `Ctrl + C` 停止并重新执行 `pnpm dev`。

### 3. 本地已修改但尚未推送到 GitHub Pages
本地看到的效果仅在本地服务器（`http://localhost:4321`），需通过 Git 推送到远程仓库触发 GitHub Actions 构建，线上博客才会同步更新。

## 小白最常用的 3 个终端命令

```powershell title="PowerShell 常用命令"
# 1. 本地实时预览（修改实时生效）
pnpm dev

# 2. 本地静态构建检查（打包测试，排查语法与链接报错）
pnpm build

# 3. 一键发布上线（自动 git add / commit / push）
.publish-blog.bat
```

> [!NOTE]
> 如果推送时遇到网络抖动中断，但在本地已完成 commit，可直接运行 `.\push-only.bat` 单独重试推送。

## 新手最后一定要知道的 4 个建议

1. **小步快跑**：每次只修改一个配置文件或一项功能，改完即在本地刷新确认，不要一次性改动几十处；
2. **本地先行**：始终养成在本地预览（`pnpm dev`）验证无误后，再推送到线上的好习惯；
3. **内容与样式解耦**：写文章只专注 `posts/*.md` 的 Markdown 语法，不要在文章内混杂大量未封装的复杂内联样式；
4. **不必焦虑代码底层**：不需要精通 Astro 或 Svelte 框架，会改配置文件和写 Markdown，你就已经是合格的博客站长了！
