# 分类和标签配置指南

> [!TIP]
> **设计思想**：
> 良好的文章分类和标签体系是长效博客的“骨架”。合理规划不仅能帮助读者快速按图索骥，也是博客侧边栏标签云、归档页面以及文章底部“相关推荐算法”准确推荐的核心依据。

---

## 一、基本概念区分

在 Firefly 博客中，分类与标签有着明确的职责边界：

* **分类（Category）**：文章的宏观领域，每篇文章建议只归属于**一个主分类**（例如：`博客搭建`、`技术笔记`、`GitHub周刊`）。
* **标签（Tags）**：文章的技术细节与关键词属性，文章可以拥有**多个标签**（例如：`[Astro, 部署上线, CI/CD]`）。

---

## 二、文章 Frontmatter 设置

在每篇 Markdown 文章（`src/content/posts/*.md`）的顶部设置分类与标签：

```markdown title="文章 Frontmatter 示例"
---
title: 我的文章标题
published: 2026-10-15
category: 博客搭建
tags: [快速起步, 部署上线, Astro]
---
```

> [!NOTE]
> **分类设计建议**：
> Firefly 主题在归档页通过 URL 查询参数（如 `/archive/?category=博客搭建`）进行统一筛选。建议保持分类粒度简洁宏观（全站通常建议 3~6 个顶层分类），具体的跨领域、细分技术关键词交由 `tags` 多标签体系来实现。

---

## 三、分类栏显示配置

### 1. 开启分类导航栏

在 `src/config/siteConfig.ts` 中，可以一键开关首页横向分类栏：

```typescript title="src/config/siteConfig.ts"
export const siteConfig: SiteConfig = {
    // 是否在首页文章列表上方显示横向分类切换栏
    categoryBar: true,
};
```

* 开启后，首页文章列表顶部会显示所有包含有效文章的分类胶囊按钮，访客可一键切换不同专题。

---

## 四、归档与跳转规则（Firefly 底层实现）

与某些传统博客框架不同，Firefly 采用了高性能的统一归档筛选路由：

1. **分类点击行为**：
   * 点击任意分类按钮，将自动跳转至：`/archive/?category=分类名称`
   * 页面仅展示匹配该分类的文章时间轴。
2. **标签点击行为**：
   * 点击标签云或文章元数据中的标签，将跳转至：`/archive/?tag=标签名称`
   * 页面仅展示匹配该标签的文章时间轴。
3. **未分类兜底**：
   * 若文章未设置 `category`，系统将自动归入“未分类”组（`/archive/?uncategorized=true`）。

## 五、为什么必须重视标签体系？（实战避坑）

Firefly 内置了基于数学相似度的高级相关文章推荐算法（位于 `src/utils/content-utils.ts`）：

```typescript title="src/utils/content-utils.ts"
// 评分体系：tagMatchScore (0-100) + titleSimilarityScore + timeFreshnessScore + categoryBonus
const tagMatchScore = jaccardSimilarity(currentTags, postTags) * 100;
```

> [!WARNING]
> **千万不要所有文章都用同一个标签**！
> 如果全站所有文章都打同一个标签（如全都打 `[博客配置]`），所有文章的标签匹配度得分永远是 100%，推荐系统就失去了区分能力。
> 正确做法：给每篇文章打 2~4 个具体的特征词（例如评论文章打 `[评论系统, Giscus, Waline]`，播放器文章打 `[音乐播放器, APlayer]`），推荐模块就能精准把相关的上下篇串联在一起。

---

## 六、最佳组织实践建议

1. **分类要克制**：不要为一两篇文章单独建一个分类，当某个主题积累了 3 篇以上文章时再设立分类。
2. **标签要统一**：避免使用大小写不一致或近义词（如不同文章分别打 `react` 与 `React`，应全站统一定义）。
3. **先大后小**：
   * 宏观专栏看分类（如：《博客搭建》）
   * 细分技能看标签（如：《评论系统》、《图床》、《代码排版》）
